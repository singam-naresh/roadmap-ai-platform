# Deployment Guide — Roadmap AI Platform

## Architecture

| Component | Platform | Method |
|-----------|----------|--------|
| Backend   | Render   | Docker (from `backend/Dockerfile`) |
| Frontend  | Vercel   | Vite static build |

---

## 1. Deploy Backend to Render (Docker)

### Steps

1. Go to [render.com](https://render.com) → **New** → **Web Service**
2. Connect your GitHub repository: `singam-naresh/roadmap-ai-platform`
3. Configure the service:

| Setting | Value |
|---------|-------|
| **Name** | `roadmap-ai-backend` |
| **Runtime** | `Docker` |
| **Dockerfile Path** | `backend/Dockerfile` |
| **Docker Context** | `backend` |
| **Health Check Path** | `/health` |
| **Plan** | Free |

4. Add **Environment Variables** (click "Add Environment Variable" for each):

| Variable | Value | Notes |
|----------|-------|-------|
| `GROQ_API_KEY` | `gsk_...` | Your Groq API key — **required** |
| `JWT_SECRET` | _(auto-generate)_ | Click "Generate" in Render |
| `ALLOWED_ORIGINS` | `https://your-app.vercel.app` | Set after Vercel deploy |
| `SPRING_PROFILES_ACTIVE` | `prod` | Activates production config |
| `PORT` | `10000` | Render free tier default |

5. Click **Create Web Service** → Render builds and deploys automatically

### Verify backend is running

```bash
curl https://roadmap-ai-backend.onrender.com/health
# Expected: {"status":"UP","service":"AI Productivity Assistant",...}
```

> **Note:** Free tier spins down after 15 min inactivity. First request after cold start takes 30–60s.

---

## 2. Deploy Frontend to Vercel

### Steps

1. Go to [vercel.com](https://vercel.com) → **New Project** → Import `singam-naresh/roadmap-ai-platform`
2. Configure:

| Setting | Value |
|---------|-------|
| **Root Directory** | `frontend` |
| **Framework Preset** | Vite |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |

3. Add **Environment Variable**:

| Variable | Value |
|----------|-------|
| `VITE_API_BASE_URL` | `https://roadmap-ai-backend.onrender.com` |

4. Click **Deploy**

### Verify frontend

Open your Vercel URL — the app should load and connect to the backend.

---

## 3. Update CORS after both are deployed

Once you have your Vercel URL, go back to Render → your service → **Environment** and update:

```
ALLOWED_ORIGINS = https://your-actual-app.vercel.app
```

Then click **Save** — Render redeploys automatically.

---

## 4. Environment Variables Reference

### Backend (Render)

```
GROQ_API_KEY=gsk_...                    # Required — from console.groq.com
JWT_SECRET=<auto-generated by Render>   # Required — long random string
ALLOWED_ORIGINS=https://...vercel.app   # Required — your Vercel URL
SPRING_PROFILES_ACTIVE=prod             # Required — activates prod config
PORT=10000                              # Required — Render free tier port
H2_CONSOLE_ENABLED=false                # Security — keep disabled
```

### Frontend (Vercel)

```
VITE_API_BASE_URL=https://...onrender.com   # Required — your Render backend URL
```

## 5. Local Development

```bash
# Backend
cd backend
# Ensure backend/.env has your GROQ_API_KEY
./mvnw spring-boot:run
# Runs on http://localhost:10000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev
# Runs on http://localhost:5173
# Proxies /api/* to http://localhost:10000
```

## 6. Troubleshooting

| Problem | Solution |
|---------|----------|
| 403 on `/health` | SecurityConfig must permit `/health` — already fixed |
| CORS error | Set `ALLOWED_ORIGINS` to exact Vercel URL (no trailing slash) |
| 500 on roadmap generation | Check `GROQ_API_KEY` is set in Render env vars |
| Frontend blank page | Check `VITE_API_BASE_URL` is set in Vercel dashboard |
| Cold start timeout | Normal on free Render tier — first request takes 30–60s |
| Docker build fails | Ensure `backend/Dockerfile` and `backend/pom.xml` are committed |
| Port mismatch | Backend must listen on `${PORT:10000}` — already configured |
